安装后，连接你自己的服务

从安装到第一次填充。

扩展不提供托管账号，也没有预设服务器。先完成上方 Docker 部署，再授权你的工作区。

  1. 安装扩展

    从 Chrome 或 Edge 商店安装并固定到工具栏。如需使用历史离线包，先解压，在 chrome://extensions 或 edge://extensions 开启开发者模式，选择“加载已解压的扩展程序”，选中含 manifest.json 的文件夹。

  2. 授权工作区

    打开扩展 Settings，输入自己服务的 HTTPS 地址（包括部署子路径），保存后选择 Connect extension。在打开的网页中登录、解锁、选择工作区，并确认本次浏览器授权。

  3. 解锁并填充

    在扩展输入工作区密码，本地解锁。访问已保存的网站，选择匹配条目并点击 Fill login，检查后自行提交。更新扩展后请刷新已打开的网站；无法填充时可手动复制。

部署与日常维护

把安全落实到每一步。

客户端加密保护存储和同步的保险库内容。它不能保护已被入侵的设备，也不能阻止被篡改的网页在解锁时窃取密码。

01 · HTTPS 与服务器

示例命令仅监听 127.0.0.1。让同机反向代理通过有效证书提供 HTTPS，并只开放必要端口；不要直接将 18741 端口暴露到公网。若代理运行在容器中，使用专用 Docker 网络连接服务。保持系统、Docker 和浏览器更新。

如在宿主机运行 Caddy，将域名解析到服务器，放行证书申请和 HTTPS 所需的 80/443 端口，并替换示例域名：

vault.example.com {
  reverse_proxy 127.0.0.1:18741
}

02 · 两种密码，各有职责

登录密码用于服务器账号认证，主密码（工作区密码）用于本地解密。为两者设置独立的强密码；主密码请在保险库之外妥善保管。忘记主密码时，即使有加密备份也无法解密。

03 · 备份与恢复

定期导出 .pvault 加密备份，另存一份到独立设备，并在独立工作区验证可恢复。导出需要账号登录密码，恢复需要导出时的主密码。明文 JSON 含全部敏感数据，请避免长期保存或上传到公共位置。

04 · 扩展与设备

只授权自己的服务器和所需工作区。在公共或共享设备上避免解锁；离开时主动锁定。按需开启悬浮面板、登录保存和通行密钥权限。设备丢失或不再使用时，在网页设置的浏览器扩展授权中撤销连接。

05 · 更新前先备份

先导出备份，再停止容器并快照整个数据卷，保留原镜像版本。拉取新镜像后，使用相同数据卷与配置重建容器；不要删除数据卷。更新后检查登录、解锁、条目和扩展连接。回退时使用匹配的旧镜像及数据快照。

06 · 填充前核对网站

检查域名与 HTTPS，再选择要填入的账号。扩展不会替你提交表单；跨站表单需额外确认。剪贴板可被其他程序读取，复制后及时清理。离线缓存只能读取已同步内容，不能代替独立备份。
